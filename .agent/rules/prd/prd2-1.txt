##  ۱. خلاصه اجرایی

### ۱.۱ هدف این فاز

فاز ۲ سیستم قیمت‌گذاری هوشمند و مدیریت چندارزی را به Orbiq اضافه می‌کند تا کاربران ایرانی بتوانند:

✅ قیمت خرید را به ارز (دلار/یورو/درهم) ثبت کنند  
✅ سه قیمت (کف/فروش/سقف) به صورت خودکار محاسبه شود  
✅ سود واقعی با در نظر گرفتن تغییرات ارز دیده شود  
✅ تاریخچه کامل نرخ ارز حفظ شود  
✅ گزارش سود با دو نگاه (تاریخی/امروز) ارائه شود

### ۱.۲ چرا این فاز مهم است؟

**مشکل فعلی:**
- قیمت‌گذاری دستی و وقت‌گیر
- عدم توانایی ردیابی سود واقعی در شرایط تورمی
- از دست دادن سود به دلیل عدم آپدیت قیمت‌ها
- نبود تاریخچه نرخ ارز

**راه‌حل:**
- قیمت‌گذاری خودکار با بازه سود قابل تنظیم
- ثبت نرخ ارز در هر تراکنش (Immutable)
- محاسبه سود واقعی vs ظاهری
- هشدار برای محصولات با سود واقعی منفی

### ۱.۳ شاخص‌های موفقیت (KPIs)

| شاخص | هدف |
|------|-----|
| زمان قیمت‌گذاری یک محصول | < ۱۰ ثانیه (از ۲ دقیقه) |
| دقت محاسبه سود | ۱۰۰٪ |
| رضایت کاربر از گزارش سود | > 4.5/5 |
| استفاده از ثبت ارزی | > 60% کاربران |

## ۹. قوانین کسب‌وکار

> [!IMPORTANT]
> این قوانین باید در تمام لایه‌های سیستم (Database, Service, UI) اعمال شوند.

### ۹.۱ قوانین نرخ ارز

#### BR-2.1: Immutability نرخ ارز
- نرخ ثبت شده هرگز قابل ویرایش یا حذف نیست
- برای اصلاح → رکورد جدید با `source='correction'`
- رکوردهای correction به رکورد اصلی reference دارند
- Audit trail کامل برای همه تغییرات

#### BR-2.2: اعتبارسنجی نرخ
- نرخ باید بزرگتر از ۰ باشد
- `confidence` باید بین ۰ تا ۱ باشد
- اگر تغییر نرخ > ۱۰٪ از آخرین نرخ → هشدار
- اگر تغییر نرخ > ۲۵٪ → نیاز به تایید مدیر

#### BR-2.3: نرخ پیش‌فرض
- اگر نرخی ثبت نشده → خطا
- هیچ نرخ هاردکد نمی‌شود
- کاربر باید حداقل یک نرخ اولیه ثبت کند

#### BR-2.4: واکشی نرخ تاریخی
- اگر نرخ دقیق آن روز موجود باشد → استفاده شود
- اگر نه → نزدیک‌ترین نرخ قبل از آن تاریخ
- اگر هیچ نرخ قبلی نبود → اولین نرخ موجود
- هشدار به کاربر که نرخ دقیق نیست

### ۹.۲ قوانین قیمت‌گذاری

#### BR-2.5: محدودیت‌های سود
```
minProfitMargin >= 0%
maxProfitMargin <= 200%
minProfitMargin < defaultProfitMargin < maxProfitMargin
تفاوت حداقل ۵٪ بین هر کدام
```

#### BR-2.6: محاسبه قیمت
```
minPrice = costPrice × (1 + minProfitMargin/100)
sellingPrice = costPrice × (1 + defaultProfitMargin/100)
maxPrice = costPrice × (1 + maxProfitMargin/100)
گرد کردن به نزدیک‌ترین roundingStep
```

#### BR-2.7: تبدیل ارز
```
priceInIRR = priceInFX × exchangeRate
همیشه نرخ فعلی استفاده می‌شود مگر اینکه کاربر تغییر دهد
نرخ دستی باید در محدوده ±۱۰٪ نرخ فعلی باشد
```

#### BR-2.8: اعتبارسنجی قیمت فروش
- قیمت < `minPrice` → هشدار قرمز + نیاز به PIN
- قیمت > `maxPrice` → هشدار زرد (بدون مانع)
- `minPrice` <= قیمت <= `maxPrice` → هشدار سبز

### ۹.۳ قوانین سود

#### BR-2.9: محاسبه و ذخیره سود
```
profitIRR = sellingPrice - costPrice (ذخیره می‌شود)
exchangeRateAtSale = نرخ فعلی (ذخیره می‌شود, Immutable)
costExchangeRate = نرخ خرید (ذخیره می‌شود, Immutable)
profitUSD = profitIRR / exchangeRateAtSale (Computed, Not Stored)
```

#### BR-2.10: فرمول‌های سود
```
profitUSD = profitIRR / exchangeRateAtSale
effectiveRate = SUM(profitIRR) / SUM(profitUSD)
currentValue = SUM(profitIRR) / currentRate
valueLoss% = (historical - current) / historical × 100
```

#### BR-2.11: تفکیک انواع سود
- **OperationalProfit** = فروش - خرید (با نرخ زمان تراکنش)
- **FXRevaluationImpact** = (نرخ امروز - نرخ خرید) × مقدار
- **NetRealProfit** = OperationalProfit + FXRevaluationImpact

#### BR-2.12: Data Contracts
- Immutable Fields هرگز تغییر نمی‌کنند
- Computed Fields محاسبه می‌شوند، ذخیره نمی‌شوند
- Versioning: breaking change = major version
- Reports به contract version مربوط به خود بسته‌اند

### ۹.۴ قوانین امنیتی

#### BR-2.13: کنترل دسترسی
- تنظیمات نرخ ارز → فقط Admin
- تنظیمات قیمت‌گذاری → Admin + Accountant
- فروش زیر کف → نیاز به PIN مدیر
- ویرایش فاکتور قدیمی → نیاز به تایید

#### BR-2.14: Audit Log
- تمام تغییرات نرخ ارز لاگ می‌شود
- تمام فروش زیرکف لاگ می‌شود
- تغییرات تنظیمات قیمت‌گذاری لاگ می‌شود
- Log شامل: user, timestamp, action, before, after

### ۱۰.۲ سناریوهای تست

#### TEST-2.1: ثبت خرید با دلار
**Given:** نرخ دلار ۸۰,۰۰۰ تومان ثبت شده  
**When:** خرید آیفون با قیمت ۱,۰۰۰ دلار  
**Then:**
- معادل ریالی = ۸۰,۰۰۰,۰۰۰ تومان
- minPrice = ۹۶,۰۰۰,۰۰۰ (۲۰٪ سود)
- sellingPrice = ۱۰۴,۰۰۰,۰۰۰ (۳۰٪ سود)
- maxPrice = ۱۲۰,۰۰۰,۰۰۰ (۵۰٪ سود)
- نرخ ۸۰,۰۰۰ در PurchaseItems ذخیره شود

#### TEST-2.2: فروش و محاسبه سود
**Given:** محصول با cost=۸۰M, نرخ خرید=۸۰K, نرخ فعلی=۸۲K  
**When:** فروش با قیمت ۱۱۰,۰۰۰,۰۰۰  
**Then:**
- profitIRR = ۳۰,۰۰۰,۰۰۰
- profitUSD = ۳۰M / ۸۲K = ۳۶۶ دلار
- exchangeRateAtSale = ۸۲,۰۰۰ ذخیره شود

#### TEST-2.3: گزارش سود تاریخی
**Given:** ۳ فروش با نرخ‌های ۷۸K, ۸۰K, ۸۲K  
**When:** مشاهده گزارش سود تاریخی  
**Then:**
- جمع سود ریالی صحیح باشد
- جمع سود دلاری با نرخ هر فروش محاسبه شود
- نرخ مؤثر = SUM(IRR) / SUM(USD)

#### TEST-2.4: فروش زیر کف
**Given:** minPrice = ۱۰۰M  
**When:** تلاش برای فروش ۹۵M  
**Then:**
- هشدار قرمز نمایش داده شود
- دیالوگ PIN مدیر نمایش داده شود
- بدون PIN فروش انجام نشود
- با PIN صحیح فروش انجام و لاگ شود

#### TEST-2.5: ویرایش فاکتور قدیمی
**Given:** فاکتور ۱۰ روز پیش، نرخ آن روز ۷۵K  
**When:** ویرایش فاکتور  
**Then:**
- نرخ ۷۵K پیشنهاد شود
- کاربر بتواند انتخاب کند (آن روز/امروز)
- هشدار تاریخ نمایش داده شود

#### TEST-2.6: تغییر شدید نرخ ارز
**Given:** نرخ قبلی ۸۰,۰۰۰  
**When:** ثبت نرخ ۱۰۰,۰۰۰ (+۲۵٪)  
**Then:**
- هشدار تغییر شدید نمایش داده شود
- نیاز به تایید مدیر
- درصد تغییر نمایش داده شود

## پیوست A: Data Contracts

### Contract Version: v1.0

#### Immutable Fields
این فیلدها پس از ایجاد **هرگز** تغییر نمی‌کنند:

**SalesItems:**
- `exchangeRateAtSale`
- `profitIRR`
- `costPrice`
- `createdAt`

**PurchaseItems:**
- `exchangeRateAtPurchase`
- `unitPrice`
- `createdAt`

**ExchangeRateEvents:**
- `rate`
- `recordedAt`
- `source`

#### Computed Fields (Never Stored)
- `profitUSD = profitIRR / exchangeRateAtSale`
- `effectiveRate = SUM(IRR) / SUM(USD)`
- `valueLossPercent`

#### Versioning Rules
- **Breaking changes** = Major version (v2.0)
- **Additions** = Minor version (v1.1)
- Historical reports bound to version at creation
- AI Prompts reference contract version

## پیوست B: Financial Truth Hierarchy

در صورت تناقض، کدام منبع معتبرتر است؟

1. **🏆 Transaction Data** (Source of Truth)
   - SalesItems, PurchaseItems, ExchangeRateEvents
   - هرگز تغییر نمی‌کنند

2. **📊 Aggregated Reports**
   - گزارش‌های روزانه/ماهانه
   - در تناقض → سطح ۱ درسته

3. **🤖 AI Interpretations**
   - تحلیل‌ها و پیش‌بینی‌ها
   - در تناقض → سطح ۲ درسته

4. **📤 User Exports**
   - Snapshot از لحظه خروجی
   - برای مقایسه، metadata چک شود
