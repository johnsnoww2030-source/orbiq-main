# مرحله ۰: آنالیز و رفع مشکلات ساختاری (قبل از Migration)

---

## ۰.۱ پیدا کردن Barrel Files

**Barrel File چیست؟**
فایلی که فقط export دارد و چندین فایل را re-export می‌کند.

**مثال Barrel File:**
```
// lib/features/auth/domain/domain.dart
export 'entities/user.dart';
export 'repositories/auth_repository.dart';
export 'usecases/login_usecase.dart';
```

**کار اول:** در پروژه‌ات جستجو کن:
- فایل‌هایی با نام `index.dart`
- فایل‌هایی با نام `exports.dart`
- فایل‌هایی که فقط `export` دارند
- فایل‌هایی با نام کلی مثل `domain.dart`, `data.dart`, `presentation.dart`

**لیست کن:** همه Barrel Files که پیدا کردی را یادداشت کن.

---

## ۰.۲ بررسی Import ها در فایل‌های Code Generation

**فایل‌هایی که Code Generation دارند:**
- فایل‌های `@Entity` (Floor)
- فایل‌های `@injectable` / `@lazySingleton`
- فایل‌های `@JsonSerializable`
- فایل‌های BLoC

**کار دوم:** هر کدام از این فایل‌ها را باز کن و Import هایش را چک کن.

**قانون طلایی:**

| ❌ غلط | ✅ درست |
|--------|---------|
| `import 'package:app/features/auth/domain/domain.dart';` | `import '../entities/user.dart';` |
| `import 'package:app/core/core.dart';` | `import '../../core/utils/helpers.dart';` |
| Import از Barrel File | Import مستقیم فایل |

---

## ۰.۳ رفع Import های نادرست

**برای هر فایل که Code Generation دارد:**

۱. لیست Import ها را ببین
۲. اگر Import از Barrel File هست، پیدا کن دقیقاً کدام فایل لازمه
۳. Import را به آدرس مستقیم تغییر بده

**مثال:**

قبل:
```dart
// lib/features/auth/data/repositories/auth_repository_impl.dart
import 'package:app/features/auth/domain/domain.dart'; // ❌ Barrel
```

بعد:
```dart
// lib/features/auth/data/repositories/auth_repository_impl.dart
import '../../domain/entities/user_entity.dart';        // ✅ مستقیم
import '../../domain/repositories/auth_repository.dart'; // ✅ مستقیم
```

---

## ۰.۴ بررسی Circular Dependencies در Injectable

**کار سوم:** فایل injection.config.dart را باز کن (اگر وجود داره)

**دنبال این الگو بگرد:**
- ServiceA به ServiceB وابسته است
- ServiceB به ServiceA وابسته است

**چطور پیدا کنیم؟**

در هر فایل `@injectable` ببین constructor چه چیزهایی می‌گیرد:

```dart
@injectable
class AuthRepository {
  final UserService userService; // ← وابستگی
  AuthRepository(this.userService);
}

@injectable
class UserService {
  final AuthRepository authRepo; // ← اگر این باشه = Circular!
  UserService(this.authRepo);
}
```

**راه حل:** اگر Circular پیدا کردی:
- یک Interface (abstract class) بساز
- یکی از کلاس‌ها به Interface وابسته باشه، نه مستقیم
